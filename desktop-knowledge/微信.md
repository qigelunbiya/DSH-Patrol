# 微信 Windows 操作指南

> 这是 DSH Patrol Desktop Automation 的初始知识库。不同微信版本的 UI Automation 暴露程度可能不同，实际操作时必须以 CURRENT desktop_snapshot / desktop_ocr 结果为准。

## 应用识别

- 常见进程名：`WeChat`、`Weixin`
- 主窗口标题通常包含“微信”。
- 首选交互顺序：CURRENT OCR + 键盘快捷键/Enter → UI Automation（仅当 CURRENT snapshot 确实暴露稳定唯一控件）→ CURRENT 视觉坐标。

## 搜索联系人

推荐流程：

1. `desktop_activate_window` 激活微信，并记住实际 `processName`（常见为 Weixin/WeChat）。
2. 发送 `Ctrl+F`，再用带同一 `processName` 的 `desktop_type_text` 输入联系人名称。
3. 用 `desktop_wait_for_target(text=<联系人>, source=ocr, scope=active-window, processName=<微信进程>, requireUnique=true)` 等待搜索结果。OCR 匹配默认容忍识别器插入的多余空白。
4. 搜索结果唯一时优先按 `Enter` 打开当前选中的第一结果。不要在 Enter 后机械地再点击同一个联系人。
5. **目标聊天确认**：马上调用 `desktop_ocr(scope=active-window, processName=<微信进程>)` 或同范围 screenshot。OCR 返回的 `window.processName/title` 必须仍属于微信；确认联系人名称出现在主聊天标题/内容区后，视为已经进入聊天并立刻继续发送步骤。不要要求联系人文字只能出现一次，因为左侧会话列表和聊天标题可以同时出现。
6. 如果 window 元数据不是微信，或 OCR 中出现“主机运维/浏览器”等明显属于后方应用的内容，视为捕获范围错误，重新激活微信并重做 window-scoped OCR；不要把这些外部文字解释成微信 UI。
7. 只有目标聊天确实未打开时才用 CURRENT OCR/键盘纠正选择；只有 `desktop_list_windows` 明确确认微信窗口已经消失，才允许 `desktop_launch_app`。禁止因为一次 OCR/点击判断不确定就关闭/重开微信、点“返回上一页”或重复整个搜索流程。

同名联系人不唯一时不要猜，应停在搜索结果等待用户进一步说明。

## 发送文字

1. 先完成上一节的“目标聊天确认”；这是发送前的硬条件。不能因为搜索结果被点击过，就假定当前聊天已经切换。
2. 可做一次 `desktop_snapshot` 探测输入区；如果 UIA 树很稀疏或找不到 Edit，立即停止猜 `QTextEdit`/className。依据刚刚同一微信窗口的 CURRENT screenshot/OCR 确认右侧主聊天区域，在本轮证据支持下点击底部空白消息编辑区，再用带 `processName` 的 `desktop_type_text` 输入。
3. 如果 CURRENT snapshot 确实给出唯一稳定的 Edit/automationId，则可用 `desktop_type_target`；这是可用时的稳定捷径，不是微信的默认前提。
4. 输入后，在可能的情况下用 CURRENT OCR/screenshot 或 UIA value 确认文本确实出现在编辑区；焦点不确定时禁止直接发送。
5. 再按当前微信设置使用 Enter 或 Ctrl+Enter。发送后重新 `desktop_ocr`/截图，确认目标会话仍是预期联系人，并看到新消息/编辑区清空等 CURRENT 状态变化后才能报告“发送成功”。仅调用 `desktop_press` 成功不等于消息发送成功。

## 发送图片 / 巡检截图

推荐使用剪贴板文件方式：

1. 浏览器巡检先产生 screenshot artifact。
2. `desktop_set_clipboard_files` 放入图片路径。Runbook 重放时可使用 `${artifact:last-screenshot}`。
3. 激活目标聊天。
4. `desktop_paste`。
5. 优先用 `desktop_wait_for_target` 等待可观察的图片预览/文件名/聊天状态；只有当前版本完全没有可匹配语义时才使用短暂 `desktop_wait`。
6. 通过 UIA / OCR 确认聊天对象和图片预览后发送。

如果图片已经以位图形式进入剪贴板，也可以直接粘贴；当前 Patrol 初版优先使用 FileDropList，便于跨浏览器巡检产物复用。

## 发送文件

1. 使用 `desktop_set_clipboard_files`。
2. 激活目标聊天窗口。
3. `desktop_paste`。
4. 确认文件预览/文件名。
5. 再执行发送。

## 常见恢复策略

- 微信窗口找不到：先 `desktop_list_windows` 重新确认实际进程名和标题；只有列表确实没有微信窗口才启动新实例，不要把单次 activate/OCR 失败等同于应用已关闭。
- 搜索框找不到：先 `Ctrl+F`，再 snapshot。
- 联系人列表不暴露 UIA：优先 `desktop_click_ocr_text`；如果需要诊断，再 `desktop_ocr` 查看 CURRENT 行级文字/坐标。
- OCR 有多个相同联系人：停止，不使用坐标猜测。
- 页面刚切换时：如果知道下一状态的控件/文字/value，使用 `desktop_wait_for_target`；只有没有任何可观察语义状态时才短暂 `desktop_wait` 后重新 snapshot。
- 消息输入偶尔落到错误焦点：不要反复 `desktop_type_text`；重新 snapshot，使用 `desktop_type_target` 绑定唯一输入控件。
- 坐标只作为最后后备；窗口位置、DPI 或版本变化后旧坐标不得直接复用。
