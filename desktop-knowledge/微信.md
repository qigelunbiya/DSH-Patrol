# 微信 Windows 操作指南

> 这是 DSH Patrol Desktop Automation 的初始知识库。不同微信版本的 UI Automation 暴露程度可能不同，实际操作时必须以 CURRENT desktop_snapshot / desktop_ocr 结果为准。

## 应用识别

- 常见进程名：`WeChat`、`Weixin`
- 主窗口标题通常包含“微信”。
- 首选定位顺序：UI Automation → 快捷键 → OCR → 坐标。

## 搜索联系人

推荐流程：

1. `desktop_activate_window` 激活微信。
2. 优先发送 `Ctrl+F`。
3. `desktop_type_text` 输入联系人名称。
4. 用 `desktop_wait_for_target(text=<联系人>, source=auto, requireUnique=true)` 等待搜索结果真正出现。它先查 UIA 名称，再回退 CURRENT OCR，避免固定 sleep。
5. 结果出现后先用 `desktop_snapshot` 判断是否可以 `desktop_click_target`。
6. 如果 UIA 没有暴露搜索结果，而联系人文字已知，优先 `desktop_click_ocr_text`（`text=<联系人>`，通常先用 exact）。它每次都会基于 CURRENT 截图重新 OCR，只有唯一匹配才点击。
7. 需要先观察 OCR 结果时使用 `desktop_ocr`；它会返回每行文字对应的绝对屏幕 `rect` 与 `center`。只有语义 OCR click 无法使用且目标仍唯一时，才直接用该 CURRENT `center` 调用 `desktop_click_coordinates`。

同名联系人不唯一时不要猜，应停在搜索结果等待用户进一步说明。

## 发送文字

1. 确认当前聊天对象名称。
2. 用 `desktop_snapshot` 找消息输入区。新版 snapshot 会保留无 name/automationId 的交互控件；如果消息区可以由 `controlType=Edit`、`className` 或 automationId 唯一识别，优先直接进入下一步，不需要先单独点击。
3. 使用 `desktop_type_target` 把稳定 UIA selector 与普通消息文本一起执行。例如 `controlType=Edit + className=<CURRENT class>`。它会先激活微信、唯一定位输入区、聚焦，再执行清空/粘贴，因此比“click-target → type-text”更不依赖残留焦点。
4. 对非密码输入区，snapshot 可能暴露 UIA `value`。需要确认普通测试消息已经进入输入区时，可用 `desktop_wait_for_target(source=uia, controlType=Edit, value=<非敏感消息片段>, match=contains)`。密码/敏感内容不得作为 value selector，密码控件本身也不会返回 value。
5. 发送动作可使用带 `processName/titleContains` 的 `desktop_press` Enter，具体取决于当前微信“Enter发送 / Ctrl+Enter发送”的用户配置；首次使用时应观察实际设置或结果。

## 发送图片 / 巡检截图

推荐使用剪贴板文件方式：

1. 浏览器巡检先产生 screenshot artifact。
2. `desktop_set_clipboard_files` 放入图片路径。Runbook 重放时可使用 `${artifact:last-screenshot}`。
3. 激活目标聊天。
4. `desktop_paste`。
5. 优先用 `desktop_wait_for_target` 等待可观察的图片预览/文件名/聊天状态；只有当前版本完全没有可匹配语义时才使用短暂 `desktop_wait`。
6. 通过 UIA / OCR 确认聊天对象和图片预览后发送。

如果图片已经以位图形式进入剪贴板，也可以直接粘贴；当前 Patrol 初版优先使用 FileDropList，便于跨浏览器巡检产物复用。

## 发送文件

1. 使用 `desktop_set_clipboard_files`。
2. 激活目标聊天窗口。
3. `desktop_paste`。
4. 确认文件预览/文件名。
5. 再执行发送。

## 常见恢复策略

- 微信窗口找不到：`desktop_list_windows`，确认实际进程名和标题。
- 搜索框找不到：先 `Ctrl+F`，再 snapshot。
- 联系人列表不暴露 UIA：优先 `desktop_click_ocr_text`；如果需要诊断，再 `desktop_ocr` 查看 CURRENT 行级文字/坐标。
- OCR 有多个相同联系人：停止，不使用坐标猜测。
- 页面刚切换时：如果知道下一状态的控件/文字/value，使用 `desktop_wait_for_target`；只有没有任何可观察语义状态时才短暂 `desktop_wait` 后重新 snapshot。
- 消息输入偶尔落到错误焦点：不要反复 `desktop_type_text`；重新 snapshot，使用 `desktop_type_target` 绑定唯一输入控件。
- 坐标只作为最后后备；窗口位置、DPI 或版本变化后旧坐标不得直接复用。
